Pohon v4 marks a major milestone: **Pohon and Pohon Pro are now unified into a single, fully open-source and free library**. You now have access to 125+ production-ready components, all available in the `pohon-ui` package.

::note
Pohon v4 requires **Nuxt 4.1 or later** due to some dependencies. Make sure to upgrade before migrating to Pohon v4.
::

This guide provides step-by-step instructions to migrate your application from v3 to v4.

## Migrate your project

### From Pohon Pro

1. Replace `pohon-ui-pro` with `pohon-ui` in your `package.json`:

::code-group{sync="pm"}

```bash [pnpm]
pnpm remove pohon-ui-pro
pnpm add pohon-ui tailwindcss
```

```bash [yarn]
yarn remove pohon-ui-pro
yarn add pohon-ui tailwindcss
```

```bash [npm]
npm uninstall pohon-ui-pro
npm install pohon-ui tailwindcss
```

```bash [bun]
bun remove pohon-ui-pro
bun add pohon-ui tailwindcss
```

::

:::div

```diff [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
-   'pohon-ui-pro',
+   'pohon-ui'
  ]
})
```

## Changes from v3

After upgrading to Pohon v4, please note the following important changes:

### Renamed ButtonGroup

The `ButtonGroup` component has been renamed to [`FieldGroup`](/docs/components/field-group):

```diff
<template>
- <UButtonGroup>
+ <UFieldGroup>
    <PButton label="Button" />
    <PButton icon="i-lucide-chevron-down" />
+ </UFieldGroup>
- </UButtonGroup>
</template>
```

### Renamed PageMarquee

The `PageMarquee` component has been renamed to [`Marquee`](/docs/components/marquee):

```diff
<template>
- <UPageMarquee :items="items" />
+ <PMarquee :items="items" />
</template>
```

### Removed PageAccordion

The `PageAccordion` component has been removed in favor of [`Accordion`](/docs/components/accordion):

```diff
<template>
- <UPageAccordion
+ <UAccordion
    :items="items"
+   :unmount-on-hide="false"
+   :ui="{ trigger: 'text-base', body: 'text-base text-muted' }"
  />
</template>
```

::note
The `PageAccordion` component was a wrapper that set `unmount-on-hide` to `false` and customized the `ui` prop.
::

### Renamed model modifiers

The `modelModifiers` shape used by [`Input`](/docs/components/input), [`InputNumber`](/docs/components/input-number) and [`Textarea`](/docs/components/textarea) has changed in v4:

1. The `nullify` modifier was renamed to `nullable` (it converts empty/blank values to `null`).
2. A new `optional` modifier was added (it converts empty/blank values to `undefined`).

```diff
- <UInput v-model.nullify="value" />
+ <UInput v-model.nullable="value" />
```

```diff
- <UTextarea v-model="value" :model-modifiers="{ nullify: true }" />
+ <UTextarea v-model="value" :model-modifiers="{ nullable: true }" />
```

Use `nullable` when you want empty values as `null`, and `optional` when you prefer `undefined` for absent values.

### Changes to Form component

The `Form` component has been improved in v4 with better state management and nested form handling. Here are the key changes you need to be aware of:

1. Schema **transformations will only** be applied to the **`@submit` data** and will no longer mutate the form's state. This provides better predictability and prevents unexpected state mutations.
2. **Nested forms must be enabled explicitly** using the `nested` prop. This makes the component behavior more explicit and prevents accidental nested form creation.
3. **Nested forms should now provide a `name`** prop (similar to `PFormField`) and will automatically inherit their state from their parent form.

```diff
<template>
  <PForm :state="state" :schema="schema" @submit="onSubmit">
    <PFormField label="Customer" name="customer">
      <UInput v-model="state.customer" placeholder="Wonka Industries" />
    </PFormField>

    <div v-for="(item, index) in state.items" :key="index">
      <PForm
-       :state="item"
+       :name="`items.${index}`"
        :schema="itemSchema"
+       nested
      >
        <PFormField :label="!index ? 'Description' : undefined" name="description">
          <UInput v-model="item.description" />
        </PFormField>
        <PFormField :label="!index ? 'Price' : undefined" name="price">
          <UInput v-model="item.price" type="number" />
        </PFormField>
      </PForm>
    </div>
  </PForm>
</template>
```

### Removed deprecated utilities

Some **Nuxt Content utilities** that were previously available in Pohon Pro have been **removed** in v4:

- `findPageBreadcrumb`
- `findPageHeadline`

These are now fully provided by Nuxt Content. Make sure to update your imports and usage accordingly.

```diff
- import { findPageHeadline } from 'pohon-ui-pro/utils/content'
+ import { findPageHeadline } from '@nuxt/content/utils'

- import { findPageBreadcrumb } from 'pohon-ui-pro/utils/content'
+ import { findPageBreadcrumb } from '@nuxt/content/utils'
```

### AI SDK migration (optional)

This section only applies if you're using the AI SDK and chat components (`ChatMessage`, `ChatMessages`, `ChatPrompt`, `ChatPromptSubmit`, `ChatPalette`). If you're not using AI features, you can skip this section.

1. Update `@ai-sdk/vue` and `ai` dependencies in your `package.json` and add [Comark](https://comark.dev) (replaces `@nuxtjs/mdc` for rendering AI responses as streaming Markdown):

::framework-only
#nuxt
:::div

```diff
{
  "dependencies": {
-   "@ai-sdk/vue": "^1.2.x",
+   "@ai-sdk/vue": "^4.0.x",
-   "ai": "^4.3.x",
+   "ai": "^7.0.x",
+   "@comark/nuxt": "latest"
  }
}
```

Add `@comark/nuxt` to your modules:

```diff [nuxt.config.ts]
export default defineNuxtConfig({
  modules: [
    'pohon-ui',
+   '@comark/nuxt'
  ]
})
```

:::

#vue

```diff
{
  "dependencies": {
-   "@ai-sdk/vue": "^1.2.x",
+   "@ai-sdk/vue": "^4.0.x",
-   "ai": "^4.3.x",
+   "ai": "^7.0.x",
+   "@comark/vue": "latest"
  }
}
```

::

2. The `useChat` composable API changed: `input` and `handleSubmit` were removed in favor of `sendMessage`, and `messages` is now a ref you set directly:

```diff
<script setup lang="ts">
  import { useChat } from '@ai-sdk/vue'

- const { messages, input, handleSubmit, status, error, reload, setMessages } = useChat()
+ const { messages, status, error, sendMessage, regenerate, stop } = useChat()
+ const input = ref('')
+
+ function handleSubmit() {
+   sendMessage({ text: input.value })
+   input.value = ''
+ }
</script>
```

3. Messages now use `parts` instead of `content`:

```diff
// When manually creating messages
- setMessages([{
+ messages.value = [{
  id: '1',
  role: 'user',
- content: 'Hello world'
+ parts: [{ type: 'text', text: 'Hello world' }]
- }])
+ }]

// In templates
<template>
- <UChatMessage :content="message.content" />
+ <UChatMessage :parts="message.parts" />
</template>
```

4. Some methods have been renamed:

```diff
// Regenerate the last message
- reload()
+ regenerate()
```

5. Replace `<MDC>` with `<Markdown>` for parts-based rendering. The `Markdown` component is purpose-built for streaming Markdown, it incrementally renders tokens as they arrive from the AI. Use AI SDK helpers and the `isPartStreaming` utility from `pohon-ui/utils/ai`.

::note
When using the `shiki` plugin, add the following CSS to your stylesheet for dark mode support:

```css [main.css]
html.dark .shiki span {
  color: var(--shiki-dark) !important;
  background-color: var(--shiki-dark-bg) !important;
  font-style: var(--shiki-dark-font-style) !important;
  font-weight: var(--shiki-dark-font-weight) !important;
  text-decoration: var(--shiki-dark-text-decoration) !important;
}
```

::

::framework-only
#nuxt

```vue
<script setup lang="ts">
import { isReasoningUIPart, isTextUIPart } from "ai";
import { isPartStreaming } from "pohon-ui/utils/ai";
import shiki from "@comark/nuxt/plugins/shiki";
</script>

<template>
  <UChatMessages :messages="messages" :status="status">
    <template #content="{ message }">
      <template
        v-for="(part, index) in message.parts"
        :key="`${message.id}-${part.type}-${index}`"
      >
        <UChatReasoning
          v-if="isReasoningUIPart(part)"
          :text="part.text"
          :streaming="isPartStreaming(part)"
        >
          <Markdown
            :value="part.text"
            :streaming="isPartStreaming(part)"
            :plugins="[shiki()]"
            class="*:first:mt-0 *:last:mb-0"
          />
        </UChatReasoning>

        <template v-else-if="isTextUIPart(part)">
          <Markdown
            v-if="message.role === 'assistant'"
            :value="part.text"
            :streaming="isPartStreaming(part)"
            :plugins="[shiki()]"
            class="*:first:mt-0 *:last:mb-0"
          />
          <p v-else-if="message.role === 'user'" class="whitespace-pre-wrap">
            {{ part.text }}
          </p>
        </template>
      </template>
    </template>
  </UChatMessages>
</template>
```
